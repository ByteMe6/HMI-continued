# HMI 5.1.1 → Minecraft 26.1.2 Port — Design

**Date:** 2026-06-10
**Status:** Approved (user, 2026-06-10)

## Goal

Port the Fabric client mod **Hold My Items 5.1.1** (built for Minecraft 1.21.11) to
**Minecraft 26.1.2**, producing a working jar: `HMI 5.1.1 (26.1.2).jar` in
`~/Downloads/HMI`. No source is available; the only input is the production jar.
The mod is CC0-1.0 licensed, so decompiling and redistributing a port is permitted.

## What the mod is

- Fabric client-side rendering mod: first-person item/hand animation overhaul.
- Lua-scripted animations via bundled **LuaJ 3.0.1** (nested jar `META-INF/jars/luaj-jse-3.0.1.jar`).
- Built-in resource pack (`resourcepacks/pack_test`) with 3D item models/textures.
- 14 active mixins (per `holdmyitems.mixins.json`) into rendering internals:
  GameRenderer, MinecraftClient, ItemStack, Camera, LivingEntity, BlockRenderManager,
  HandRenderType, HeldItemRenderer, ItemRenderer, JavaMethod (LuaJ safety),
  UseDuration, UsingItem, HangingSign, ItemRenderState.
- Entrypoint: `com.holdmylua.source.LuaTestHMI` (main).
- Extra compiled classes not in mixins.json (InGameHudMixin, FishingBobberMixin,
  PrevLivingMixin, GameRendererMixin under client/) — port them as-is but treat the
  mixins.json list as the active set.

## Environment facts (verified 2026-06-10)

- Minecraft **26.1.2** is a stable release with Fabric support.
- **26.1+ is unobfuscated**: Yarn and intermediary are discontinued; mods compile
  against Mojang's official names directly. No refmaps; `remapJar` → `jar`.
- Toolchain: **Loom 1.15** (`net.fabricmc.fabric-loom` plugin), **Gradle 9.4.0**,
  **Java 25** (system has Java 21 — JDK 25 must be installed or toolchain-provisioned),
  Fabric Loader **0.19.3**, Fabric API **0.151.0+26.1.2**.
- The 5.1.1 jar is compiled against **intermediary** names (`net/minecraft/class_XXXX`),
  no refmap (mixin annotations hold intermediary strings directly).
- 26.1 changed rendering internals (GPU chunk-geometry storage, render layers
  auto-assigned from sprite contents). Fabric API renamed modules to match mojmap
  (e.g. `ItemGroupEvents` → `CreativeModeTabEvents`); `FluidModel` replaces
  `FluidRenderHandler`; `BlockColorRegistry` replaces `ColorProviderRegistry`.

## Approach (approved)

1. **Remap** the production jar: intermediary → Mojang official mappings for 1.21.11
   (tiny-remapper + mapping-io; Mojang proguard mappings from piston-meta, intermediary
   tiny from FabricMC). Output namespace == the namespace used by 26.1.2 development.
2. **Decompile** the remapped jar with Vineflower → readable Java source.
3. **Scaffold** a Fabric Loom 1.15 project for 26.1.2 (Gradle 9.4.0, Java 25,
   Loader 0.19.3, Fabric API 0.151.0+26.1.2) and drop in the decompiled source,
   assets, resource pack, and nested LuaJ jar.
4. **Port**: fix compile errors from 1.21.11→26.1.2 API changes; re-validate every
   mixin target against the unobfuscated 26.1.2 client jar; update `fabric.mod.json`
   (minecraft `~26.1.2`, java `>=25`, loader/fabric-api bounds, keep id/version/
   entrypoints). **Constraint:** the Lua script API surface (globals, function names,
   semantics exposed to animation scripts/resource packs) must remain unchanged so
   existing animation packs keep working.
5. **Build & verify** (user-selected depth: maximum):
   a. `gradle build` succeeds.
   b. Static audit: every mixin target class/method exists in 26.1.2 with matching
      signature (the 26.1.2 jar is unobfuscated and directly inspectable).
   c. Launch the dev client (`runClient`, no account needed) on the local AMD GPU
      and confirm the mod initializes without crashing; capture the log.
6. **Deliver**: copy the built jar to `~/Downloads/HMI/HMI 5.1.1 (26.1.2).jar`.

## Alternatives rejected

- **Port from Hold-My-Items-Neo source** — NeoForge, MC 1.21.1, based on HMI 1.0.4;
  wrong loader and years behind 5.1.1.
- **Wait for official port** — none exists; 5.1.1/1.21.11 is the latest release.

## Risks

- 1–3 of the 14 mixins likely hook methods that were refactored in 26.1's rendering
  overhaul; each needs an equivalent injection point found by reading 26.1.2 code.
  Worst case: a sub-feature (e.g. hanging-sign or fishing-bobber tweak) needs a
  redesigned hook or is temporarily disabled — any such compromise must be reported
  explicitly in the final summary.
- Decompiler artifacts (invalid switch shapes, synthetic names) need manual repair.
- LuaJ 3.0.1 is Java-version-agnostic bytecode (compiled for ancient JVMs) — expected
  to run fine on Java 25; verify at runtime.
- Client launch on headless/Wayland may need xvfb or native display; if the GPU/display
  path fails, fall back to reporting build + static audit results and say so plainly.

## Success criteria

1. Jar builds reproducibly from the new project.
2. All active mixins apply (verified statically; no `MixinApplyError` at launch).
3. Dev client reaches the title screen with HMI initialized (log evidence).
4. Lua scripts and bundled resource pack load without errors in the log.
5. Deliverable jar present at `~/Downloads/HMI/HMI 5.1.1 (26.1.2).jar`.
