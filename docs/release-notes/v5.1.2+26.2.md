Unofficial port of **Hold My Items 5.1.1** (by sapling, CC0) to **Minecraft 26.2** (Fabric).

**Requirements:** Minecraft 26.2, Fabric Loader 0.19.3+, Fabric API, Java 25+.

The Lua script API is unchanged — existing animation packs keep working.

### What's new since v5.1.1+26.1.2

- **Ported to Minecraft 26.2.** Rebuilt against 26.2's reworked feature-render
  pipeline: the item quad loop moved to the two-pass `buildGroup` → `prepareSubmit`
  split, `MultiBufferSource`/`OutlineBufferSource` were removed, and the
  hand/arm submit hooks were renamed (`submitHandsWithItems` / `submitArmWithItem`).
- **Held-item visuals fixed for 26.2:** beds render both halves again, held hanging
  signs render the `attached` state (top chain bar restored), and bucket liquids are
  inset to avoid z-fighting. Opaque quads are now submitted before translucent ones so
  buckets no longer render see-through under 26.2's depth-writing translucent pipeline.
- **Bundled `pack_test` 3D item set restored and repaired for 26.2:** the original
  `*_3d` element models/textures are back, out-of-range face UVs are clamped to 0–16,
  and mismatched animation `.mcmeta` files were removed — held buckets/boats bake as 3D
  items again with zero bake warnings.
- **Resource pack metadata updated:** declares `min_format`/`max_format` and
  `supported_formats` as required by 26.2 (plus a legacy `pack_format: 46` for older
  clients).

### Known limitation

Blocks with *special* geometry (chests, banners, skulls) lose their dynamic geometry in
the "held item as 3D block" mode — 26.1 removed the special-block re-render path. Bells
still render via their dedicated hook.
